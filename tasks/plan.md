# 本地开发编排实施计划

项目配置 → 本地任务快照 → LangGraph / SQLite → Codex 执行器与命令验证 → diff / 报告。

保持一个核心流程，以接口替换 coding agent；清除旧文本原型。先 CLI，运行数据与目标仓库分离，修改仅在 worktree。检查命令由用户注册，不能由模型更改。

## 顺序

1. 配置、注册、持久化、锁：证明本地多仓库状态可靠。
2. worktree、命令执行和检查：证明隔离、失败结果与超时清理。
3. LangGraph / SQLite：替身执行器完成修改、失败、修复和重启恢复。
4. Codex CLI：结构化审核、会话与阶段结果保存，真实模型冒烟。
5. CLI、文档、清理、全量验证和本地提交。

任务状态仅在 todo.md 记录。

## 本地可视化界面

复用现有 Store / CLI / workflow，增加仅监听 127.0.0.1 的 HTTP 服务和 React 界面。HTTP 进程启动独立 CLI 工作进程，避免编码和 Git 操作阻塞页面；关闭页面不停止任务，正常关闭服务会暂停其工作进程。继续遵守同一数据目录只运行一个任务的约束。

界面包含仓库筛选、新建/编辑/移除注册、任务创建与预算、阶段进度、检查结果、事件时间线、日志尾部和产物下载、暂停与恢复。新增任务可先保存为待执行。旧 CLI 数据直接读取，旧任务没有事件历史时只显示当前状态。

视觉：雾蓝 #eff3f8、纸白 #ffffff、深墨 #152641、灰蓝 #56637c、钴蓝 #315ce8、琥珀 #a46d19。Bahnschrift / 系统中文标题、Segoe UI / 微软雅黑正文、Cascadia Code 等宽数据。左侧仓库栏 + 中部任务列表 + 右侧详情，阶段轨道作为核心视觉；不展示虚构百分比。窄屏依次堆叠并保留操作入口。

先验证 API 的来源校验、任务互斥、受限文件读取和恢复，再验证实际浏览器的仓库表单、任务创建、暂停/恢复和日志刷新。实时状态采用有取消和串行调度的短轮询，同源部署，避免额外消息服务。

## 风险

- Windows SQLite：先安装与打开/关闭验证。
- agent 中断：checkpoint + 阶段结果 + session ID；未完成动作核对当前文件，不虚构 exactly-once。
- 降低测试：检查配置来自任务快照，审核读取实际 diff，保留日志。
- 环境缺依赖：显式 setup 与错误日志，不共享其他项目 node_modules。
- API/权限失败：进入可恢复错误状态，不放宽沙箱或假成功。
